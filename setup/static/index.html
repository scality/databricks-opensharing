Endpoint

The hostname must be a registered rest-endpoint on CloudServer, the S3 service in both RING and ARTESCA. An anonymous request to its root answers 403 when it is registered and 400 (InvalidURI) when it is not. Check runs that probe.

Nothing else to configure. This is the shape a Databricks recipient needs, since it fetches the presigned URLs from this host.

The server's JVM is given a truststore built from the CA below. The recipient must trust the same CA, which rules this case out for Databricks Serverless but not for a client next to the storage.

The certificate must name the host in the S3 endpoint. If that is an IP address, the Subject Alternative Name must include the IP.

These checks run from this host. They show that the S3 endpoint resolves and its certificate is trusted here — not that Databricks can reach it. Databricks fetches presigned URLs from that hostname over the public internet from its NCC egress addresses, which this tool cannot test from inside your network. A green result here does not prove that path.

The recipient profile carries a bearer token. Its stated expiry is advisory — nothing enforces it, so access ends when the token is rotated and not before.
